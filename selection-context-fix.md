# Selection Context Fix - Avoid Full File Reads

## Problem

When matisse sent selection context to Claude Code, it used the `@file#L100:50` syntax which caused Claude Code CLI to **read and inline the entire file** into the prompt, regardless of the line number. This led to:

1. **Token bloat**: A 2,291-line file being read when only 2 lines were selected
2. **"Prompt is too long" errors**: Combined with 424 messages of conversation history, the prompt exceeded context limits
3. **Unexpected behavior**: Users expected only selected text to be sent, not entire files

## Investigation

Research into Claude Code's `@file` reference syntax revealed:
- `@filename` causes the **entire file** to be inlined into the prompt
- Line number syntax (`@file#L100-L200`) is VS Code-specific and doesn't prevent full file reads in the CLI
- The `@` syntax is designed to give Claude immediate full-file access, not partial content

Looking at similar Emacs packages:
- **monet.el**: Sends actual selected text + metadata (no `@` references)
- **claude-code-ide.el**: Sends actual selected text + metadata (no `@` references)

Both packages avoid `@` file references for selection context to prevent unwanted full file reads.

## Solution Implemented

Modified `matisse--format-selection-context` (line 3519) to:
1. **Remove `@` file reference syntax** - No longer triggers full file reads
2. **Send actual selected text** - Only the content user selected
3. **Include file path and line range** - For context without file read
4. **Match monet.el behavior** - Consistent with established patterns

### Before
```elisp
;; Old behavior - triggered full file read
"@/path/to/file.md#L100:0-L102:50 - <selected text>"
```

### After
```elisp
;; New behavior - sends only selected content
"File: /path/to/file.md (lines 100-102)

<selected text>"
```

## Benefits

1. **No surprise file reads**: Only selected content is sent
2. **Token efficient**: 2 lines selected = 2 lines sent (not 2,291 lines)
3. **Prevents "Prompt is too long" errors**: Dramatically reduces prompt size
4. **Matches user expectations**: Selection behavior is predictable
5. **Consistent with other tools**: Aligns with monet.el and claude-code-ide.el

## Impact

- **Breaking change**: No - still sends selection context, just different format
- **User visible**: Selection context format changes slightly (cleaner actually)
- **Backwards compatible**: Yes - Claude understands both formats

## When to Use `@file` References

Users can still explicitly type `@filename` in their prompts when they **want** the full file read. The `@` syntax is still useful for:
- Explicitly requesting full file context
- Small files where full content is desired
- Typed by user, not auto-generated by selection tracking
